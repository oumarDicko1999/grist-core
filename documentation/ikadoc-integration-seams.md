# IkaDoc Integration Seams

This fork treats IkaDoc/Owarelin support as a runtime layer around Grist. Product logic belongs in `app/ikadoc` where possible. Upstream Grist files are patched only at stable seams needed to enter IkaDoc mode, inject runtime config, gate capabilities, or replace upstream product surfaces.

## Owned IkaDoc Boundary

- `app/ikadoc/*`: IkaDoc capability model, runtime config parser, editor admission contracts, host/editor event bridge, and Owarelin runtime events.
- `app/server/lib/IkaDoc*`: backend admission, editor endpoint, runtime session registry, active document method classification, and runtime policy.
- `app/client/ui/IkaDocEditorControls.ts`: IkaDoc save/discard/status controls.
- `app/client/ui/IkaDocThemeBridge.ts`: Owarelin/Angular Material token bridge for IkaDoc runtime mode.
- `test/node_compat.js`: test-only local Node compatibility shim for focused IkaDoc server tests.

## Rebase Rules

- Keep new product code under `app/ikadoc` or `app/server/lib/IkaDoc*` unless a stable upstream seam is required.
- Do not move IkaDoc authority into Grist org, workspace, account, or role decisions.
- Any new upstream file patch must be added to this ledger with its reason and regression test.
- Any new capability gate must default to denied when IkaDoc runtime config is absent, malformed, stale, or missing the capability.
- Route, websocket method, boot-config, and UI shell assumptions must have unit tests where they can be tested without a live browser.
- Browser-to-host editor messages use the versioned `owarelin:*` event bridge only. Do not reintroduce legacy unversioned `ikadoc:grist:*` messages.

## Runtime Auth Contract

IkaDoc remains the authority for browser access, tenant isolation, document ownership, and editor lifecycle. The fork must not treat Grist orgs, workspaces, anonymous users, API keys, or browser-supplied headers as authority for IkaDoc runtime documents.

Runtime editor access uses the `IKADOC_GRIST_GATEWAY_SESSION` HTTP-only cookie plus backend admission. The dedicated editor endpoint registers the admitted session in the in-process runtime registry. Document REST/profile routes may revalidate a missing local registry entry only by calling the IkaDoc backend admission endpoint with the browser cookie header and the session id. If IkaDoc returns any denial, malformed response, unreachable backend result, expired session, tenant mismatch, actor mismatch, disabled module, or permission denial, Grist fails closed and does not register the session.

Runtime document requests that bypass the editor entrypoint, such as `/api/docs/:docId` REST calls and `/api/docs/:docId` websocket upgrades, are admitted through Traefik forward-auth. IkaDoc validates the browser session, Grist gateway session, tenant scope, source document, and requested path first. On success, IkaDoc returns signed assertion headers: `X-IkaDoc-Grist-Session`, `X-IkaDoc-Grist-Path`, `X-IkaDoc-Grist-Timestamp`, and `X-IkaDoc-Grist-Signature`. Traefik copies only these backend-authored response headers to Grist. The fork validates the HMAC signature, timestamp age, and absolute request path before converting the request into an IkaDoc runtime identity. Query strings are deliberately excluded from the signature; the signed path for `/api/docs/:docId?clientId=...` is `/api/docs/:docId`.

The fork deliberately does not accept a browser-controlled `X-IkaDoc-*` session header as proof. Headers only count after Traefik overwrites them with the backend forward-auth response. All document authorization still resolves to the admitted runtime config, and `docAuth` grants access only to the exact admitted Grist document id or short URL id.

Security invariants:

- No direct Grist-owned account, org, workspace, sharing, profile, or document-creation surface may become authoritative for IkaDoc runtime sessions.
- Runtime REST, websocket, and profile requests must share the same IkaDoc session registry, signed forward-auth verifier, and backend admission fallback.
- Backend admission failures are authorization failures, not anonymous fallbacks.
- Capability checks must default to denied for export, attachments, structure edits, formula edits, access management, external egress, assistant, proposal, fork, copy, and admin operations unless IkaDoc explicitly grants them.
- Live reverse proxy configuration may expose the fork only behind IkaDoc forward-auth and session cookies; direct public Grist exposure is out of contract.
